# 날씨 카드 — 날씨별 배경 효과 (1단계)

작성일: 2026-09-11

## 무엇을 만드나

카드 배경에 날씨에 맞는 움직이는 효과를 넣는다. 비 오는 날은 카드 표면에
물방울이 맺히고, 눈 오는 날은 눈이 내리고, 바람이 세면 낙엽이 날리고,
맑은 날은 해가 빛난다.

1단계의 범위는 **화면에서 움직이는 것**과 **JPG 저장**까지다.
MP4 내보내기는 2단계에서 이 엔진을 재사용해 따로 만든다.

## 왜 캔버스인가

효과를 CSS 애니메이션으로 만들면 두 가지가 깨진다.

첫째, html2canvas는 카드를 복제해서 캡처하므로 복제본에서 CSS 애니메이션이
0% 키프레임으로 되돌아간다. 화면에서 보던 장면이 저장되지 않는다.

둘째, CSS 애니메이션은 영상으로 구울 수 없다. 2단계에서 전부 다시 만들어야
한다.

캔버스는 두 문제를 모두 피한다. 캔버스는 살아있는 픽셀 상태를 들고 있으므로
복제되어도 보이는 그대로 캡처되고, 같은 엔진이 2단계에서 프레임을 찍어
영상으로 만든다.

## 파일 구성

| 파일 | 하는 일 | 변경 |
| --- | --- | --- |
| `style.css` | 카드 배경색·글자 | 캔버스 배치 규칙 추가 |
| `effects.js` | 입자 엔진 (신규) | 신규 |
| `app.js` | 날씨 데이터, 카드 채우기, 저장 | 엔진 호출 + 저장 형식 |
| `index.html` | 화면 구조 | 캔버스 2개, 저장 형식 칩 |
| `test.html` | 장면 선택 규칙 검사 (신규) | 신규 |

`app.js`는 이미 500줄이라 입자 코드를 더하면 손대기 어려워진다. 2단계가
`effects.js`만 가져다 쓰므로 처음부터 분리한다.

## 색과 효과를 따로 관리한다

카드는 지금 `data-theme`으로 배경색을 정한다. 여기에 `data-fx`를 더해
효과를 따로 둔다.

바람 부는 맑은 날은 `data-theme="clear" data-fx="wind"`가 된다. 하늘색은
맑은 날 그대로 두고 낙엽만 날린다. 새 색 테마는 추가하지 않는다.

## 장면 선택 규칙

```
1. 비·눈·뇌우·안개  → 그 날씨 효과 (바람 무시)
2. 그 외 풍속 6m/s 이상 → 낙엽
3. 나머지            → 맑음이면 햇살, 흐리면 구름
```

풍속은 이미 `current.wind_speed_10m`으로 받고 있다 (카드 하단 "바람" 칸).
API 호출은 바뀌지 않는다.

이 규칙은 순수 함수 `pickScene(weatherCode, windSpeed)` 하나로 구현하고
`test.html`에서 검사한다.

## 캔버스 두 장

카드 안에 투명한 캔버스를 두 장 깐다.

```
배경 그라데이션    ← style.css
  뒤쪽 캔버스      ← 멀리: 햇무리, 흐릿한 구름, 먼 눈송이
    글자·숫자      ← index.html
  앞쪽 캔버스      ← 가까이: 유리에 맺힌 물방울, 날리는 낙엽
```

앞뒤로 나누면 깊이감이 생긴다. 물방울은 카드 표면에 붙은 느낌이어야 하므로
앞쪽, 햇무리는 글자 뒤에서 퍼져야 하므로 뒤쪽이다.

글자 가독성은 앞쪽 캔버스에서만 위험하다. 앞쪽에는 작고 투명한 것만 올리고
덮는 면적을 제한한다. 특히 주간 카드는 7줄이 빽빽하므로 더 조심한다.

### 크기와 선명도

캔버스는 화면에 보이는 축소 크기가 아니라 실제 1080px 크기로 그린다.
카드 크기를 쇼츠(1080×1920)와 정사각(1080×1080) 사이에서 바꾸면 캔버스도
따라 바뀌면서 입자를 다시 뿌린다.

### 성능

초당 30프레임으로 다시 그린다. 다른 탭으로 넘어가면 멈춘다.
운영체제의 "동작 줄이기" 설정이 켜져 있으면 움직이지 않고 한 장면만 그린다.

## 엔진이 밖으로 내보이는 것

```
Effects.mount(cardEl)     캔버스 두 장을 만들어 카드에 넣는다
Effects.setSize(w, h)     카드 크기가 바뀌면 다시 뿌린다
Effects.setScene(name)    장면을 바꾼다
Effects.start() / stop()  애니메이션 제어
```

`app.js`는 이 넷만 호출한다. 입자가 어떻게 생겼는지는 `effects.js` 안에
갇혀 있어서, 장면을 고치거나 더할 때 `app.js`를 건드리지 않아도 된다.

## 장면 7개

**맑음** — 배경 오른쪽 위 주황색 번짐 자리에 해를 놓는다. 뒤쪽에서 빛줄기가
아주 느리게 돌고 밝기가 숨쉬듯 오르내린다. 앞쪽에 작은 빛 알갱이가 떠다닌다.

**흐림** — 뒤쪽에 흐릿한 구름 덩어리 서너 개가 서로 다른 속도로 가로지른다.
느린 것이 뒤, 빠른 것이 앞이다.

**비** — 앞쪽 캔버스가 주인공이다. 카드 표면에 물방울이 맺혀 있고 위쪽
하이라이트와 아래쪽 옅은 그림자로 볼록해 보인다. 가끔 한 방울이 무거워지면
아래로 흘러내리며 자국을 남기고 잠시 뒤 다시 맺힌다. 뒤쪽에는 옅은 빗줄기가
사선으로 지나간다.

**눈** — 뒤쪽에 크고 흐릿한 눈송이가 느리게, 앞쪽에 작고 또렷한 눈송이가
좌우로 살랑이며 떨어진다. 유리에 달라붙어 움직이지 않는 눈송이를 몇 개 섞어
카드에 눈이 쌓인 느낌을 만든다.

**뇌우** — 비 장면을 더 어둡고 굵게 깔고, 2~5초마다 한 번씩 카드 전체가
아주 짧게 번쩍인다. 번쩍일 때만 갈라진 번개 줄기가 스친다.

**안개** — 반투명한 안개 띠가 가로로 아주 느리게 흐른다. 카드 가장자리를
살짝 더 뿌옇게 해서 시선이 안으로 모이게 한다.

**바람** — 갈색·주황·노랑 낙엽이 사선으로 가로지르며 회전한다. 뒤쪽에 작고
느린 잎, 앞쪽에 크고 빠른 잎을 두어 공간감을 만든다.

## JPG 저장

저장 버튼 위에 형식을 고르는 칩을 추가한다. 카드 크기 칩과 같은 모양이다.

```
저장 형식   [ JPG ]  [ PNG ]
            ↑ 기본
```

JPG는 파일이 가볍고 인스타그램에 올리기 좋다. 다만 투명을 지원하지 않으므로
배경색을 명시적으로 채워야 한다. 부드러운 그라데이션에서 색이 계단처럼 끊겨
보일 수 있어 품질은 92%로 잡고, 거슬릴 때를 위해 PNG를 남겨둔다.

저장되는 파일 이름의 확장자도 형식에 따라 바뀐다.

## 가장 큰 위험

html2canvas가 캔버스 두 장의 그림을 제대로 가져가는지 확신할 수 없다.
이것이 안 되면 화면에는 눈이 내리는데 저장한 파일에는 눈이 없다.

**구현의 첫 작업으로 이것부터 확인한다.** 캔버스에 눈에 띄는 도형을 그려놓고
저장해서 그 도형이 파일에 있는지 본다.

안 될 경우의 대비책은 캔버스를 뺀 상태로 카드를 찍은 다음 그 위에 캔버스
그림을 직접 합성하는 것이다. 이 합성 경로는 2단계 MP4에서 어차피 필요하므로
헛수고가 아니다.

## 확인하는 방법

**규칙 검사** — 이 프로젝트는 `npm` 없이 굴러가는 것이 장점이므로 테스트
도구를 새로 들이지 않는다. `test.html` 한 장을 만들어 브라우저로 열면
`pickScene`의 통과·실패가 보이게 한다. "풍속 8m/s인데 비가 오면 물방울이
나와야 한다" 같은 경우들을 담는다.

**장면 확인** — 눈 오는 날을 기다릴 수 없으므로 주소 뒤에 `#fx=snow`를
붙이면 그 장면을 강제로 띄우는 장치를 넣는다. 장면 7개 × 카드 2종 = 14가지를
눈으로 확인한다. 이 장치는 사용자가 효과를 미리 볼 때도 쓸 수 있다.

## 1단계에서 하지 않는 것

- MP4 내보내기 (2단계)
- 새 색 테마 추가 — 배경색은 지금 것을 그대로 쓴다
- 효과 세기를 사용자가 조절하는 기능
